## Design Specificity Verdict

**High specificity in the visual language, template-grade in composition and decision surfaces. The design system is better than the design.**

The four-channel signal spectrum, the gold→cyan cold-start narrative, the `browser cache → GPU` route line, and the sandbox starter page are decisions with product-specific reasons. But on a 1440×1000 window the persuasion happens in a 376×409px scroll box while 1036×730px shows a static preview. Measured mid-turn: raw token stream at `880→1024`, list viewport ends at `764` — 289px below the fold in a container that never scrolls to it.

The product's claim is asserted, never demonstrated. "Opaque origin" / "Scripts isolated" are 10.88px muted text with no proof and no interaction.

**Deterministic scan: 12 findings, exit 2, all advisory. Zero in `src/ui/`, `src/App.tsx`, `src/index.css`.** All 12 in `src/sandbox/` — 11 `design-system-color` (`fs.ts:87–129`, `runtime.ts:104`), 1 `design-system-font-size` (`fs.ts:90`). **All 12 false positives**: DESIGN.md documents the sandbox as a different visual world using hex and a system stack on purpose. Detector artifact: `#63e6d1` appears in DESIGN.md prose but is still flagged — it reads the structured palette block, not narrative.

**In-page overlay found 15 anti-patterns in host UI** the CLI cannot see: 5× `undersized-ui-text` (9.92px), 3× `tiny-text` (10.88px), 2× `wide-tracking`, 4× `dark-glow`, 1× `flat-type-hierarchy`. `dark-glow` and `flat-type-hierarchy` are the brief correctly winning (documented "Glow Means Alive Rule", deliberate 1rem ceiling). The type-weight finding is not a false positive — see Priority Issue 5.

## Priority Issues

### [P0] Opening the model picker disables the working product
`state.tsx` `selectModel` sets `phase: 'idle'` unless selected == loaded; `Chat.tsx` gates composer, starters and empty-state copy on `phase === 'ready'`. Browsing the dropdown kills every input while the engine is loaded and warm. Nothing marks the loaded model — the checkmark marks the *selected* one. Recovery affordance is a cyan "Switch model" under "DOWNLOAD 1.6 GB". Three models appear twice with identical labels. `window.__llmcoder.phase` still reports `"ready"`, so the CDP harness cannot catch it.
**Fix:** separate selected from loadable; run turns against `loadedId`; mark the loaded row with `--signal-live`; offer "Keep current".
**Command:** `/impeccable harden`

### [P1] The machinery built to prove the claim is not on screen
Two mechanisms. (a) The live token stream is 289px below the fold — per-token updates bypass the store via `liveStream`, so `Chat.tsx`'s auto-scroll on `[messages, progress, generating]` never follows it; smooth scroll can't converge on a moving target. (b) The Console reads `0 console lines` on arrival though starter `app.js` logs on boot — reproduced independently (`getConsole().length === 0`, `starterLogsOnBoot: true`); a first-mount race between `sandboxBridge.attach()` and the iframe's first log. Reload makes it appear.
**Fix:** StreamBox drives its own scroll with an at-bottom guard, `behavior: 'auto'` while generating; buffer pre-attach console messages and flush on `ready`.
**Command:** `/impeccable harden`

### [P1] A no-op write reports success in the channel that means "changed"
A 123s turn produced seven consecutive green checkmarked `Write index.html · 838 B` cards with an unchanged preview. `ToolCallCard`'s trailing icon reflects mechanical completion; `detailLine` prints resulting bytes. Neither knows whether content changed. Write-green is documented as "now resident here".
**Fix:** `projectFS.write` returns whether content differed; mute the channel and print `no change · 838 B`; treat two consecutive unchanged writes as a stop condition.
**Command:** `/impeccable harden`

### [P1] Failures are truncated, unstyled, and offer no way forward
`src/index.css:693–701` applies `white-space: nowrap; text-overflow: ellipsis` to `.tool-call small`; every failure reason routes through it with no `title` and no expansion. `src/llm/tools.ts:93` produces an actionable 200-char message that renders as `index.html already exists with 838 characters…`. Terminal failures render as ordinary body prose with no icon, no Alert Red, no retry — while `ModelPicker` already ships a correct `.inline-error` with `role="alert"`. The stats line beneath reads like success.
**Fix:** scope nowrap to `.tool-call strong`/`code`; let `small` wrap at 3 lines; route terminal failures through `.inline-error` with a cause-sized action.
**Command:** `/impeccable clarify`

### [P2] The type system violates its own Small-And-Tracked Rule
DESIGN.md:403 states "Below 0.7rem, letter-spacing opens to 0.055em and weight rises to 650… dense on purpose, never faint." `src/index.css:239–246` sets `font-size: 0.68rem; letter-spacing: 0.055em` and **no font-weight** — so `.brand p`, `.section-heading p`, `.storage-line`, `.workspace-status`, `.model-option small` render at weight 400. Only `.version` (650) and `.message > span` (700) comply. `.chat-empty small` has the same gap. The overlay independently flagged these as faint.
**Fix:** add `font-weight: 650` to that selector group. One declaration; DESIGN.md already specifies it.
**Command:** `/impeccable typeset`

## Persona Red Flags

**Alex (power user)** — Returning: 6.3s to ready, composer auto-focused. First visit: no. The model select is **tab stop #0**, so his first instinct is the P0 trap. `⌘K`, `⌘/`, `⌘1/2/3`, `⌘Enter` all unbound; documented shortcuts live only in the empty state his first message destroys. Cold start hands him `Qwen3-0.6B`, the model PRODUCT.md says doesn't reliably build pages.

**Sam (screen reader + keyboard)** — `role="status"` on `GenerationStatus` re-announces every second because `useElapsedSeconds` ticks `{seconds}s` inside the live region: a 123s turn = 123 unstoppable announcements. `StreamBox` carries a comment explaining it is `aria-hidden` to avoid exactly this, and the timer reintroduces it. No skip link — he tabs through every `.tool-path` in the transcript to reach the composer. Workspace tabs come after the composer in DOM order. "Seed example" has no accessible name below 1140px (`aria-label: null, title: null`, text `display:none`); neighbours survive on `title` alone, contradicting DESIGN.md. Reset's confirmation is silent while model-delete's is correctly labelled.

**Riley (stress tester)** — At 390px `.message-list` stops scrolling internally and grows to 1270px, pushing the composer to y=1665 on an 844px screen (821px below fold) and preview to y=1863. `console.log(NaN)` prints `null` (`JSON.stringify(NaN)` is `"null"`; fallback only catches `undefined`). One 4000-char log wraps to 25 rows with no per-line clamp. Error badge isn't clickable. Refresh mid-flow is handled well.

**Dana (skeptical engineer, from PRODUCT.md)** — Everything built to convince her is present and none aimed at her. Route line and shard counter in a 376px rail; raw stream off-screen; origin guarantees the faintest text with nothing to click. No way to falsify the wrapper hypothesis herself. If her one turn hits the repeat loop she watches seven green success cards produce nothing.

## Minor Observations

- Model nicknames have no axis: Fast / Smart / Alternate / Step up / Page builder / Reasoning / Largest. Only "Page builder" says what a model is for, and it's the one that works.
- `Download`/`Source` render under `{!isCached && !isLoading}` — "once, then cached here" is removed the instant the wait begins.
- `5.1 GB used of 15.1 GB` moves, has no explanation, offers no action.
- Model shrank `styles.css` to 88 bytes and the tree marked it authored-green: destructive shrink and thoughtful rewrite are the same signal.
- Assistant claimed "reloaded the preview" — it has no reload tool. Model claims carry tool-result authority.
- Files tree gives 250px to 3 rows, ~600px dead column.
- `v0.1.0` at 4.2:1 is the only string below AA.
- `visibility: hidden` on inactive view panels correctly leaves the tab order and a11y tree — verified.

## Questions to Consider

1. Success metric is belief but surface mode is Operate — why no third state where mid-generation takes over the workspace?
2. What single interaction would let a skeptic falsify "it's a wrapper" in five seconds?
3. Is the 0.6B default hospitality or self-sabotage?
4. The transcript models the log; nothing models the state. Where is the diff and the undo?
5. Should a failed turn cost the user anything? Mote knew at round 3 and continued 90 seconds.
6. The Unsupported screen is the best-written surface in the product. Why does none of that voice reach the screens where things merely go wrong?
